Version 01.01	15 minutes dev	2 minutes CPU	3 minutes test		20 minutes

I wanted to implement another Basic Computer Games app. The one I chose was
Trap. I liked the game, and it's not a variant you see very often.
To start off, as I worked on the initial design, I asked Claude if it had
access to the book, and if it could determine how it was played. He could.
Or rather, he said he could. Massive error in his version: selecting numbers
that trap a number wins. You could win every game by selecting 1 to 100. 
Obviously not good.
For the initial version, I got Claude to understand the game rules, and to 
give it classic style font: something from the 50's. It was a nice first
pass. As always, plenty of items to follow up with.


Version 01.02	10 minutes dev	3 minutes CPU	2 minutes test		35 minutes

The most significant defect was that there are times where you make a move
and no response is shown. It makes the game unplayable. I asked Claude to
resolve. The first attempt did not work. I showed Claude a screenshot to
make it more clear. That did result in the issue being found and fixed.


Version 01.03	8 minutes dev	0 minutes CPU	2 minutes test		45 minutes

The font sizes were small that I expected. I made some adjustments.


Version 01.04	6 minutes dev	1 minute CPU	3 minutes test		55 minutes

For a nice effect, I wanted the text to appear as if it was being typed.
Small delays between letters and spaces. The first attempt worked well.
There are some additional nuances I want to add, but this already is
better.


Version 01.05	4 minutes dev	0 minute CPU	1 minute test		1 hour

Before, the order of events after a guess didn't matter - the effect was
instant. Now with the delay of printing, the order stood out. I changed the
order to be the submit button is disabled, the UI guess fields empty, the 
focus goes back the first guess field, the text is updating in the character 
by character method, and when that completes, the submit button in enabled.
That sounds like a lot of steps. But most of that was already the order: it
was 3 lines of code moved to implement.
This worked on the first attempt from Claude.
There are still some minor changes needed.
